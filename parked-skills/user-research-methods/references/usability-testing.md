# Usability testing and click tests

## Test plan skeleton

- **Objective:** the decision this test informs, phrased as a falsifiable question ("can merchandisers configure a price rule without documentation?").
- **Participants:** 5 per distinct user type; screener criteria (role, tool experience, exclusions).
- **Setup:** prototype fidelity and known dead ends, moderated vs unmoderated, recording consent.
- **Tasks:** 3-6, each a realistic goal with context, not instructions. Give the goal ("you need the spring collection visible on the storefront by Friday"), never the path ("click Catalog, then..."). Define per task: starting point, success criteria (behavioral), and failure signals.
- **Metrics:** completion, error type, time only if it matters, confidence rating post-task, SEQ (single ease question) per task.
- **Moderation script:** intro (thinking aloud, testing the design not you, no wrong answers), neutral probes ("what are you looking at?", "what did you expect?"), rescue policy (when to assist, and log it as a fail).

## Facilitation rules

- Never react to success or failure; both are data.
- When asked "is this right?", return it: "what would you expect?"
- Note the moment of first hesitation per task; it usually marks the design problem more precisely than the failure point.

## Debrief and severity

Log issues as: task, what happened, how many participants, severity (blocker / major / minor / polish), evidence clip or quote. Route the log to research-synthesis, and to design-critique when the fix goes into iteration.

## First-click and tree tests

Use for navigation and findability questions before building flows. First-click: show a static screen, one task, record where they click first - first-click success strongly predicts task success. Tree test: text-only IA, "where would you find X" - tests labels and structure without visual design. 15-30 participants unmoderated; report success rate and directness per task, and confusion hotspots.
