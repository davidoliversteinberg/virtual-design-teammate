# Surveys and card sorting

## Survey design

- One construct per question; no double-barrels ("fast and reliable"), no absolutes ("always/never"), no jargon the respondent didn't use first.
- Prefer behavior recall over prediction: "In the past month, how many times did you..." beats "How likely are you to...".
- Scales: 5-point labeled Likert, keep direction consistent, include "Not applicable" where honest. Randomize option order for preference lists.
- Length: under 7 minutes; state it upfront. Every question must map to an analysis plan - if you can't say what you'll do with the answer, cut it.
- Open-ends: max 2, placed late, with specific stems ("What nearly stopped you from...").
- Sampling: report n, response rate, and channel bias (an in-app survey samples engaged users only). For segment comparisons, check cell sizes before claiming differences; under ~30 per cell, report directionally only.
- Pilot with 3-5 people watching them answer aloud; fix every hesitation.

## Card sorting

- **Open sort** (users create groups and names): use to discover mental models before designing IA. 15-20 participants, 30-60 cards, cards = real content items in user language, no category-sounding card names.
- **Closed sort** (users place cards into your categories): use to validate a proposed IA. Report placement agreement per card; under 60% agreement = the category or the label is wrong.
- Analysis: similarity matrix, standardized category labels, dendrogram if the tool provides one. Route resulting structure to information-architecture, validated by a tree test.
